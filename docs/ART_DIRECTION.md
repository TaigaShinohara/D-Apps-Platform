# アプリ詳細ページのアート方針

2026-11-17。D-Appsの詳細ページ、一覧からの導線に適用する。

役割は「どんな道具かを、使う前に想像できること」。主役は一つの実物資料とアプリ名。画面や機能例を見せられるときはそれを選び、ロゴやキャラクター素材しかない場合は、余白を設けてその形を見せる。利用者が用途と状態を先に理解できるよう、素材の説明と対応環境は短くまとめる。

| 目的                           | 選択と理由                                                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| アプリごとの個性を見せる       | 本体の画面、アート、ブランド色を先頭の面に使う。面の色は素材やテーマの近い色から取り、文字とのコントラストはサイト側で整える。         |
| 別の作品でも迷わず探せる       | サイト共通の文字、余白、角丸、言語切替を使う。本文と配布ボタンは同じ基準で読めるようにする。                                           |
| 配布状況と見た目を誤解させない | 実画面・ストア画像・機能例・ロゴは画像下の短い説明で区別する。素材が未確認の作品は機能説明を大きく組み、製品画面に見える図は置かない。 |

雰囲気は、静か・具体的・作品ごとの色。背景と画像に色を集め、本文は明るい無彩色を保つ。控えめな角丸と境界線で面を分ける。主役と案内を競わせる装飾、装飾だけの動き、出どころが分からない画面素材を避ける。

良い例は、ImageCrateの画像選択画面を大きく取り、タイトルとGitHubへの入口を同じ読み順に置くこと。悪い例は、アプリ名を隠すほどの装飾や、実際の素材のように見える未確認のモックを足すこと。

全作品をChromeのPC幅と320px幅で確認した。公開中のyoriAIと比較すると、画面を大きく見せることで入手欄が下がったため、配布中のアプリには冒頭から入手欄へ移動するリンクを置いた。うろぼえ・QR一気よみ・KageCamは素材を確認できなかったため、D-Apps共通色と説明文で構成した。

## ホームの一覧

配布中のアプリ、開発中・過去のアプリ、公開スキルを探す場面では、アイコンと名前を最初に見せる。アプリのアイコンは確認できる配布素材を使い、素材のない作品やスキルには用途を示す図柄を使う。カードの上部にそれぞれの色を添え、用途・対応環境・配布状況・リンクは同じ読み順と文字色で揃える。
